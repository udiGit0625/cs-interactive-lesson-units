מה פירוש log₂(n)?

הדף מיועד לתלמידים שכבר למדו יעילות וסיבוכיות זמן ריצה, אך טרם הכירו לוגריתמים. מתחילים מדוגמה, מגלים את הכלל, ומיישמים אותו בניתוח לולאות C#.

שלב 1 · מתחילים מדוגמה

כמה פעמים נדרש לחלק את המספר 64 ב־2 עד שמגיעים ל־1?

נחלק שוב ושוב את המספר ב־2. בכל לחיצה ייחשף הצעד הבא, משמאל לימין.

הרעיון המרכזי: מספר החלוקות ב־2 הדרוש כדי להגיע מ־64 ל־1 הוא 6. לכן log₂(64) = 6.

הכיוון ההפוך: כפל חוזר ב־2

נתחיל ב־1. בכל צעד נכפיל ב־2, עד שנגיע ל־64. ההמחשה מתקדמת יחד עם לחיצות החלוקה.

2⁶ = 64⇔log₂(64) = 6

בדוגמאות הנוספות מופיעות חזקות של 2, כך שאפשר להגיע בדיוק ל־1 בחלוקה חוזרת ב־2.

שלב 2 · מנסחים כלל

מהו לוגריתם?

לוגריתם שואל: לאיזו חזקה צריך להעלות את הבסיס b כדי לקבל את המספר הנתון x?

logb(x) = ?⇔b? = x

לדוגמה, log₂(32) = 5 משום ש־2⁵ = 32. הבסיס הוא 2, המספר הנתון הוא 32, והתשובה היא המעריך 5.

בשלב זה נעסוק בעיקר בחזקות שלמות ובמספרים חיוביים. בהגדרה הכללית של לוגריתם ממשי חייבים להתקיים b > 0, b ≠ 1, x > 0.

נסו לשנות את המעריך

החזקה: 2⁵ = 32
הלוגריתם: log₂(32) = 5
שלב 3 · מעמיקים

מה משתנה כשבסיס הלוגריתם אחר?

אותה שאלה בדיוק, אבל במקום להכפיל או לחלק ב־2 משתמשים בבסיס אחר. למשל log₁₀(1000) = 3, כי 10³ = 1000.

שלוש דוגמאות שכדאי להכיר

log₂(16) = 4 כי 2⁴ = 16
log₃(81) = 4 כי 3⁴ = 81
log₁₀(100) = 2 כי 10² = 100
log₅(1) = 0 כי 5⁰ = 1

שלב 5 · פתרון מודרך

מנסים לפתור — ואז משווים לפתרון

מה נדרש מכם? בכל דוגמה קראו את השאלה, נסו למצוא בעצמכם את המעריך המתאים (אפשר לרשום במחברת), ורק לאחר מכן לחצו על „הציגו את הפתרון” כדי לבדוק את דרך החשיבה שלכם. אין צורך להקליד תשובה בשלב זה.

דוגמה א: חשבו log₂(128)

חשבו: לאיזו חזקה צריך להעלות את 2 כדי לקבל 128?

הציגו את הפתרון

2⁷ = 128, ולכן log₂(128) = 7.

דוגמה ב: חשבו log₁₀(10000)

נסו לכתוב את 10000 כחזקה של 10.

הציגו את הפתרון

10⁴ = 10000, ולכן log₁₀(10000) = 4.

דוגמה ג: פתרו את המשוואה log₃(x) = 4

מצאו את המספר x המתאים לבסיס 3 ולמעריך 4.

הציגו את הפתרון

לפי ההגדרה x = 3⁴ = 81.

שלב 6 · מספרים שאינם חזקות מדויקות

ומה אם המספר אינו חזקה של הבסיס?

עד עכשיו בחרנו מספרים כמו 32 או 128, שהם חזקות מדויקות של 2. אבל מהו log₂(50)? אין מעריך שלם שכאשר מעלים בו את 2 מקבלים בדיוק 50.

נחפש תחילה בין אילו שתי חזקות עוקבות של 2 נמצא המספר 50:

2⁵ = 32 < 50 < 64 = 2⁶

לכן הלוגריתם נמצא בין 5 ל־6:

5 < log₂(50) < 6
חשוב: הלוגריתם של מספר חיובי אינו חייב להיות מספר שלם. במקרה הזה log₂(50) ≈ 5.64. את הערך המקורב ניתן לחשב במחשבון; להבנת הדוגמאות שלנו מספיק לדעת שהוא בין 5 ל־6.

איך זה קשור ללולאה שמחלקת מספר שלם?

ב־C#, כאשר n מטיפוס int, הפעולה n = n / 2 שומרת רק את המנה השלמה. למשל 25 / 2 = 12.

עבור n = 50 נקבל את הרצף הבא (משמאל לימין):

50/ 225/ 212/ 26/ 23/ 21

בוצעו 5 חלוקות. זהו החלק השלם של log₂(50), כלומר ⌊5.64⌋ = 5.

הסימון ⌊x⌋ פירושו המספר השלם הגדול ביותר שאינו גדול מ־x. לדוגמה: ⌊5.64⌋ = 5. בלולאה שתנאי העצירה שלה הוא n > 1, מספר האיטרציות הוא ⌊log₂(n)⌋ עבור n ≥ 1.
שלב 7 · ממספר צעדים לזמן ריצה

למה log מופיע בחישוב יעילות?

כאשר בכל איטרציה מחלקים את גודל הבעיה בבסיס קבוע (למשל 2 או 10), מספר האיטרציות גדל בקצב לוגריתמי, ולא בקצב לינארי.

לולאה א — חלוקה ב־2

public static void Loop2(int n)
{
    while (n > 1)
    {
        n = n / 2;
    }
}

לולאה ב — חלוקה ב־10

public static void Loop10(int n)
{
    while (n > 1)
    {
        n = n / 10;
    }
}

נניח ש־n הוא מספר שלם חיובי, וחלוקה בין משתני int ב־C# מחזירה את המנה השלמה. מספר האיטרציות בכל אחת מהלולאות הוא ⌊log_b(n)⌋ עבור n ≥ 1 ו־b הוא 2 או 10, בהתאמה. למשל, כש־n = 20, לולאה א פועלת 4 פעמים: 20 → 10 → 5 → 2 → 1.

גובה העמודות יחסי למספר האיטרציות עבור הקלט שנבחר.

מסקנה חשובה: מספר האיטרציות בלולאה א נקבע לפי log₂(n), ובלולאה ב לפי log₁₀(n), בהתאמה. מכיוון שמספר האיטרציות חייב להיות שלם, המספר המדויק הוא ⌊log₂(n)⌋ בלולאה א ו־⌊log₁₀(n)⌋ בלולאה ב. סיבוכיות זמן הריצה היא O(log₂(n)) ו־O(log₁₀(n)), בהתאמה. בשני המקרים מקובל לרשום בקיצור O(log(n)).
קישור לחומר שכבר למדתם: אתם מכירים את הסימון O ואת המושג סיבוכיות זמן ריצה. החידוש כאן הוא זיהוי הסיבוכיות הלוגריתמית: בלולאה שמחלקת את n בכל צעד במספר קבוע גדול מ־1, מספר האיטרציות גדל בקצב לוגריתמי.
שלב 8 · אתגר מסכם

משימת יעילות: שתי לולאות — שני בסיסים

נתונות שתי הפעולות הבאות. הניחו n ≥ 1, וכל פעולה בסיסית מתבצעת בזמן קבוע.

פעולה A — חלוקה ב־2

public static void A(int n)
{
    int count = 0;
    while (n > 1)
    {
        count++;
        n = n / 2;
    }
    Console.WriteLine(count);
}

פעולה B — חלוקה ב־10

public static void B(int n)
{
    int count = 0;
    while (n > 1)
    {
        count++;
        n = n / 10;
    }
    Console.WriteLine(count);
}
שלוש שאלות שונות: א. חשבו מה יודפס עבור הקלט המסוים n = 1000. ב. הכלילו: כתבו נוסחה למספר האיטרציות לכל n ≥ 1 (לא רק ל־1000). ג. קבעו את סיבוכיות זמן הריצה של כל פעולה בסימון O, ללא צורך בנוסחה מדויקת למספר האיטרציות.

סעיף א — מה יודפס עבור n = 1000?

סעיף ב — מספר האיטרציות לכל n ≥ 1

כתבו את נוסחת החישוב של מספר האיטרציות המדויק שתבצע הלולאה (מספר שלם) לכל ערך של n ≥ 1.

הקלידו בתוך הסוגריים המרובעים רק את הביטוי הלוגריתמי, למשל בצורה log₂(n). הסימון ⌊ ⌋ (החלק השלם כלפי מטה, Math.Floor) כבר מופיע.

סעיף ג — סיבוכיות זמן הריצה

כתבו את הסיבוכיות של כל פעולה. הקלידו רק את הביטוי שבין הסוגריים של O( ).

O()O()

הציגו פתרון מלא לכל הסעיפים

א. הפעולה A מדפיסה 9: הערכים לאחר החלוקה הם 500, 250, 125, 62, 31, 15, 7, 3, 1. הפעולה B מדפיסה 3: 100, 10, 1.

ב. מספר האיטרציות המדויק: ⌊log₂(n)⌋ עבור A, ו־⌊log₁₀(n)⌋ עבור B (ל־n ≥ 1).

ג. זמן הריצה: O(log₂ n + 1) ו־O(log₁₀ n + 1), בהתאמה. עבור n ≥ 2 נהוג לקצר ל־O(log₂ n) ו־O(log₁₀ n); שתיהן גם O(log n). תוספת ה־1 משקפת את העבודה הקבועה גם במקרה n = 1.

שימו לב להבדל בין מספר האיטרציות המדויק לבין סיבוכיות זמן הריצה: בסיס הלוגריתם משפיע על מספר האיטרציות, אך אינו משנה את מחלקת הסיבוכיות.
